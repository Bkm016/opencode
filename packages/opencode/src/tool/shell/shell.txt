Run terminal commands and short scripts. Use python for complex scripts. Communicate directly, not through shell output.
Do not use shell commands as substitutes for dedicated file tools: use glob for filenames, grep for content searches, read for file contents, and the available editing/writing tools for changes.

Local environment: ${os}, ${shell}.
- workdir defaults to the current directory; set it instead of changing directories in command. Temporary directory (already exists): `${tmp}`.
- For SSH, set host to an SSH config alias or user@ip; do not invoke ssh in command. Remote scripts are fed through stdin to `bash -s` without a PTY; use bash syntax, not local shell quoting, and workdir refers to the remote directory. Account for the script input when running commands that read stdin. Key-based authentication is required; no interactive password, and unavailable hosts fail fast.
- Quote paths containing spaces and verify the parent directory before creating files/directories.
- Run independent commands in parallel; sequence dependencies using the shell rules below. Do not use newlines as command separators (quoted strings may contain newlines).
- Dependencies also apply across tools: wait for a prerequisite to succeed before starting any call that consumes its result. Do not place a file edit and a command that uses the edited file in the same parallel batch.
${shellNotes}
- timeout is in milliseconds (default ${defaultTimeoutMs}). Output beyond ${maxLines} lines or ${maxBytes} bytes is truncated with full output retained in a file. Use read with offset/limit or the grep tool on that file; do not pre-truncate output with shell commands.

Git and GitHub:
- Only commit, amend, push, or create PRs when explicitly requested.
- Before committing, inspect `git status`, `git diff`, and `git log --oneline -10`; stage only intended files, never secrets. Match the repo's commit-message style.
- Do not change git config, skip hooks, use interactive -i, force-push, or create empty commits without explicit authorization. If a commit fails, fix the issue and create a new commit rather than amending.
- Before a PR, inspect status, diff, remote tracking, and all included commits and changes against the base branch. Use gh for GitHub operations and return the PR URL.
